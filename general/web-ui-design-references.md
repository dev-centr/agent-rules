# Web UI design references

When asked for good web design, better visual polish, a redesign, or inspiration from strong website designs, load skill **`web-ui-design-references`** before writing markup or styles.

## Why

Open-ended design prompts cause models to regress to repetitive defaults (purple/blue gradients, nested bordered cards, generic icons in rounded squares, raw utility color sprawl). Grounding work in curated examples and a locked semantic token contract prevents drift.

## Where the catalog lives

- Curated reference list: `general-knowledge` -> `docs/modules/ROOT/pages/reference/notable-web-ui-designs.adoc` (published under `/general-knowledge/reference/notable-web-ui-designs/`).
- Companion design contract: `reference/ai-site-design-contract.adoc`, `explanation/constrained-ai-web-design.adoc`, and `how-to/tighten-an-ai-built-site.adoc`.

## Recording entries

Every site added to the catalog records:

1. **Live URL**
2. **Date added (`YYYY-MM-DD`)** — required minimum so future readers know which design era earned inclusion
3. **Direct Wayback Machine archive snapshot in source** — ensures local readers and agents can inspect the historical design directly even without the published docs site
